# T-0408: Android notification queue and WorkManager sync

- Status: active
- Phase: 4.2 / Automatic collection and owner dashboard integration
- Depends on: T-0407

## Goal

Automatically queue policy-approved metadata-only notification events into the existing local event outbox and schedule bounded WorkManager sync, with no manual operational action.

## In scope

- Convert approved metadata events into validated local outbox envelopes with no text payload.
- Schedule existing constrained WorkManager sync after a bounded local insert; no listener network call.
- Keep text/redaction rows local-only and outside the outbox.
- Add deterministic unit tests for envelope generation, queue gating, and no-text payload.

## Out of scope

- Dashboard rendering, deployment, text upload, manual queue/sync UI, or adding a foreground service/wake lock.

## Acceptance checks

- [ ] Automated: approved metadata produces one valid local pending event; blocked/text content does not enter payload.
- [ ] Automated: listener schedules sync but never opens a network connection directly; Android tests/build pass.
- [ ] Manual: phone synthetic event enters and leaves the outbox through the hosted API without inspecting content.
- [ ] Battery/privacy: no polling, no direct collector network, no text upload.

## Battery note

- Expected callbacks/queries per day: notification callbacks only; sync is existing constrained WorkManager batching.
- Expected rows/upload bytes per day: one metadata envelope per deduplicated approved lifecycle event; small JSON payload, bounded by existing 250-event/256 KiB batch.
- Location/foreground service/wake lock impact: none.

## Privacy note

- Data classes touched: metadata package/digest/kind/time/timezone/redaction count only.
- Redaction/retention impact: text remains local-only and seven-day retained; never enters outbox.
- New permission or secret: none.
