# T-0419: Notification analytics read model

- Status: active
- Phase: 4.3 / Notification intelligence and dashboard experience
- Depends on: T-0418

## Goal

Expose authenticated, deterministic daily, weekly, and monthly notification-activity aggregates from lifecycle metadata, with honest completeness and empty states.

## Read first

- `docs/PRIVACY-SECURITY.md`
- `docs/BATTERY.md`
- `packages/database/src/event-store.ts`, `apps/api/src/app.ts`, notification analytics reader, and their tests

## In scope

- Aggregate activity totals, source ranking, hourly distribution, update/clear balance, and deterministic burst windows.
- Date-range validation, authenticated API responses, and Android parsing.
- Empty, unavailable, and incomplete states that never infer notification meaning or message counts.

## Out of scope

- Notification content, sender/contact data, app-specific parsing, new collectors, visual dashboard redesign, AI claims, or new permissions.

## Acceptance checks

- [x] Daily, weekly, and monthly aggregate queries are deterministic, authenticated, and metadata-only.
- [x] Source ranking, hourly distribution, update/clear balance, and burst windows are covered by synthetic tests.
- [x] Empty/incomplete/unavailable states are explicit and do not claim inactivity or message counts.
- [x] Contract, API/database, and Android reader checks pass.
- [x] Privacy/battery check confirms read-only owner-initiated networking with no collector polling or new data classes.

## Battery note

- Expected callbacks/queries per day: unchanged Android callbacks; owner-initiated dashboard reads only.

## Privacy note

- Redaction/retention impact: none.
- New permission or secret: none.
