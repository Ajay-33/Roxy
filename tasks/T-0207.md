# T-0207: Hosted validation environment and migration runner

- Status: in progress
- Phase: 2 / App usage
- Depends on: T-0205

## Goal

Provide the minimal hosted environment required to run T-0206 without a laptop, USB cable, or `adb reverse`: an HTTPS API, managed PostgreSQL, repeatable schema migration, and verified aggregate-only phone sync.

## Approved deployment decisions

- API: Render Free web service.
- Database: Supabase Free PostgreSQL, in the closest compatible shared region to the API.
- Availability: an external 10-minute probe calls a public, payload-free `/health` endpoint to avoid Render's 15-minute idle spin-down during the three-day validation.
- Access: public HTTPS endpoint protected by a fresh hosted-validation bearer credential.
- Budget: free tiers only; services and validation data are removed after T-0206.

## Scope

- Deploy the existing API as a single Render Free HTTPS service; do not add cloud collectors, analytics, AI services, or third-party data processors beyond the approved health probe.
- Provision a managed PostgreSQL database and keep its credentials in provider-managed secret storage.
- Add a repeatable migration runner that records applied migration IDs and applies `packages/database/migrations/0001_events.up.sql` before the API serves traffic.
- Document a migration preflight, backup/snapshot step, verification query, and rollback/recovery notes. Do not run destructive down migrations against a database containing validation data.
- Configure the API only with the hosted database URL and a new 32+-character device credential held in secret storage.
- Use Supabase's SSL-enforced IPv4 shared session pooler for the Render service; do not expose database credentials to the phone.
- Pair the phone to the HTTPS endpoint, verify offline retry and idempotent replay with aggregate-only `usage.bucket` events, and record only counts and safe error codes.

## Acceptance checks

- [ ] Automated: migration runner has tests for a fresh database and an already-migrated database.
- [ ] Automated: API starts only after required migrations have succeeded.
- [ ] Manual: HTTPS health/API request succeeds with the hosted credential; unauthenticated request is denied.
- [ ] Manual: phone pairs with the hosted endpoint and syncs aggregate-only buckets after an offline interval, without USB or `adb reverse`.
- [ ] Manual: replay does not add duplicate `usage.bucket` rows; daily totals match the stored aggregate rows.
- [ ] Documentation: provider, region, monthly spend limit, secret locations, migration procedure, recovery procedure, and service teardown steps are recorded without secrets.
- [ ] Privacy: no raw UsageEvents, app labels, credentials, database URLs containing passwords, or production payloads appear in logs, fixtures, screenshots, or task records.

## Battery note

- This task may use the existing WorkManager network-constrained sync only. It must not add polling, a foreground service, or a wake lock.
- The external 10-minute HTTP health probe does not contact the phone or database and has no phone battery impact.
- Before T-0206, record expected sync wake frequency, bytes/day, and rows/day for the chosen validation schedule.

## Rollback notes

- If deployment or migration verification fails, stop the hosted API, revoke the hosted device credential, and keep the phone queue local for retry.
- Restore the managed database from its pre-migration snapshot if required; do not apply destructive down migrations to validation data.

## Handoff

- T-0206 remains blocked until every hosted prerequisite passes. Its Day 1 starts only after the phone has been paired to the hosted HTTPS endpoint.
