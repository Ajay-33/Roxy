# T-0417: Deterministic notification metadata analytics

- Status: done
- Phase: 4.2 / Owner analytics
- Depends on: T-0416

## Goal

Turn metadata-only notification events into useful, deterministic owner analytics: volume over time, app ranking, busy windows, and arrival/dismissal breakdowns.

## Delivered

- Authenticated `GET /v1/notifications/analytics` aggregates existing notification metadata by local day, hour, event type, and source package with deterministic ordering.
- Alerts shows arrival/clear counts, busiest hour, and the top local app label/count. It never renders notification text.
- A debug-only phone probe returns aggregate counts only, allowing end-to-end qualification without exposing labels or notification contents.

## Verification record

- Automated: `pnpm check`, Android `testDebugUnitTest`, `assembleDebug`, and `git diff --check` passed on 2026-08-22.
- Phone/server: installed the build on the paired phone and called the aggregate-only debug probe. The hosted endpoint returned success with five events, five arrivals, zero clears, and a top-source count of three. The collector health check reported notification and usage collection active, both with zero queued rows.
- Privacy/battery: uses only already-stored notification metadata; no text, sender, title, body, action, image, raw payload, polling, foreground service, or direct collector networking.
