# T-0106: Add paired WorkManager sync with backoff

- Status: done
- Phase: 1 / Durable Sync
- Depends on: T-0103, T-0105

## Goal

Schedule paired event sync only when a network is available, with exponential backoff and no foreground service or polling loop.

## Acceptance checks

- [x] Automated: debug build succeeds with WorkManager.
- [x] Automated: scheduled work requires network and uses exponential backoff.
- [x] Manual: pairing credential is entered visibly and survives process restart without source/APK embedding.
- [x] Failure state: unpaired worker does no network work and displays a visible pairing-needed state.

## Battery note

- Expected callbacks/queries per day: owner-triggered enqueue plus OS-managed retry only.
- Expected rows and upload bytes per day: up to 250 events or 256 KiB per batch after pairing.
- Location/foreground service/wake lock impact: none; no foreground service or wake lock.

## Privacy note

- Data classes touched: local synthetic events and device credential.
- Redaction/retention impact: no event payload logs; credential is encrypted in Android Keystore.
- New permission or secret: INTERNET permission for explicit sync; credential is owner-entered, local-only.

## Verification record

- Automated checks: Android debug build passed; API tests passed; worker request uses `NetworkType.CONNECTED` and 30-second exponential WorkManager backoff.
- Manual checks: on the connected Android 15 phone, a visible owner-entered pairing survived process restart; a synthetic event was acknowledged by the local API and the refreshed pending queue became zero. PostgreSQL confirmed persisted test events.
- Not run and why: long-duration offline/backoff timing is covered by T-0107.
