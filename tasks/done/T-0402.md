# T-0402: Listener lifecycle and metadata-only events

- Status: done
- Phase: 4 / Notifications
- Estimate: 1–4 hours
- Depends on: T-0401

## Goal

Introduce a visible, owner-controlled Android notification listener that records only policy-approved metadata events locally, with explicit lifecycle and revocation states and no upload path.

## In scope

- Declare a `NotificationListenerService` only for the Roxy app and make its Android Notification Access settings handoff visible after the T-0401 explainer.
- Read the T-0401 enablement and per-package policy before handling a notification; blocked and disabled states must result in no local event.
- Define and persist the smallest metadata-only local event representation needed for later notification tasks: event ID, event kind, observed UTC instant, observed IANA timezone, source package identifier, and safe lifecycle metadata only.
- Explicitly exclude title, body, actions, intents, images, tokens, remote views, people/contact data, and extras from the event representation and logs.
- Surface listener connected/disconnected and access-revoked states in the owner UI without implying collection is healthy when it is not.
- Add a Room migration and deterministic unit coverage for disabled/blocked gating and metadata-only event construction.

## Out of scope

- Notification update/group deduplication (T-0403), sensitive-field redaction (T-0404), selected-app text mode/retention (T-0405), upload/sync/API/database-host changes, or AI use.
- Reading, persisting, logging, testing with, or displaying real notification title/body content, contact data, action data, images, tokens, or extras.
- Installed-app enumeration, network calls from the listener, foreground service, wake lock, or polling.

## Battery note

- Expected callbacks/queries per day: event-driven notification callbacks only; no polling. Exact callback rate is user/app dependent and will be measured in T-0406.
- Expected rows and upload bytes per day: at most one local metadata event per policy-approved callback before T-0403 deduplication; zero upload bytes because sync is out of scope.
- Location/foreground service/wake lock impact: none; no foreground service or wake lock.
- Required physical-phone measurement: verify access grant/revocation, listener reconnect, safe event-count behavior, and battery attribution during a representative notification day in T-0406.

## Privacy note

- Data classes touched: local package identifier, event kind, UTC instant, observed timezone, and minimal listener lifecycle metadata only.
- Redaction/retention impact: T-0404 must redact any future sensitive fields before persistence; this task never reads them. Retention is not introduced here.
- New permission or secret: Android Notification Access special access is requested only after the T-0401 explainer; no normal runtime permission or secret.

## Implementation notes

The listener must return immediately for disabled or blocked policy. It must never make a network call. Do not inspect notification extras as a shortcut to classify or log content. Metadata event fields and Room migration must use UTC instants plus the observed IANA timezone; event IDs must be device-generated UUIDv7 values and stable enough for later idempotent upload.
