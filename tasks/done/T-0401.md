# T-0401: Notification Access explainer and package policies

- Status: done
- Phase: 4 / Notifications
- Estimate: 1–4 hours
- Depends on: T-0312

## Goal

Give the owner a clear, reversible Notification Access setup flow and local, per-package collection-policy controls before any notification listener or notification content collection is introduced.

## In scope

- Add an owner-facing explainer that describes Notification Access, its value, what will and will not be collected, and how to revoke it in Android Settings.
- Keep notification collection disabled until the owner explicitly enables it and completes the system-settings step.
- Define an explicit local package-policy model with `blocked` and `metadata-only` policies; default to blocked for authenticators, password managers, banking apps, and owner-selected packages.
- Provide a visible local UI for reviewing and changing a package policy without displaying or storing notification text.
- Surface a visible safe state when Notification Access is not granted, has been revoked, or notifications remain disabled.
- Add deterministic unit tests for the policy defaults, owner override, and permission-status display model.
- Document the pre-listener boundary and the settings/revocation behavior in the task record and applicable privacy/design documentation if behavior changes.

## Out of scope

- A `NotificationListenerService`, notification callbacks, listener lifecycle, event persistence, upload, sync, or API/database changes (T-0402).
- Notification update/group deduplication (T-0403), field redaction implementation (T-0404), selected-app text collection or retention (T-0405).
- Any network call, background worker, foreground service, wake lock, new secret, or changes to existing pairing credentials.
- Capturing, logging, putting in fixtures, committing, or sharing real package labels, notification metadata, or notification text.

## Privacy note

- Data classes touched: local owner preference for collector enablement and local package policy only; no notification payload, title, text, actions, intents, images, tokens, or remote-view data.
- Redaction/retention impact: metadata-only remains the future default; blocked-package policy is established before a listener exists. No retention behavior is introduced.
- New permission or secret: no Android manifest permission, listener service, or secret in this task. The owner may voluntarily grant/revoke the existing Android Notification Access special access through Settings.

## Implementation notes

Use the platform Notification Listener Settings handoff only after the explainer. Treat Android's current listener-access state as UI status, not evidence that collection is running. Persist only the smallest local policy needed for later phases; do not enumerate installed packages or introduce a listener ahead of T-0402. Follow the package categories and no-log rules in `docs/PRIVACY-SECURITY.md`.
