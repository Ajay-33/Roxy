# T-0411: Automatic app-usage collection, aggregation, queueing, and bounded WorkManager sync

- Status: done
- Phase: 4.2 / Automatic collection and owner dashboard integration

## Goal

When the owner has granted Usage Access and paired Roxy, automatically collect bounded app-usage observations, make local 15-minute aggregates, queue only aggregate buckets, and request constrained sync—without a manual operational action.

## Battery note

- Expected callbacks/queries per day: WorkManager target every 30–60 minutes while enabled; bounded overlapping UsageStats query each run.
- Expected rows and upload bytes per day: local observations/buckets depend on app transitions; upload only newly deduplicated aggregate buckets, within 250 events/256 KiB batches.
- Location/foreground service/wake lock impact: none.
- Required physical-phone measurement: include this collector in the three baseline/three enabled-day protocol in `docs/BATTERY.md` after implementation.

## Privacy note

- Data classes touched: local raw app-usage observations and local 15-minute aggregate buckets; only aggregate package identifier/duration buckets are queued.
- Redaction/retention impact: raw observations remain on-device; no app content, labels, notification data, or text enters this path.
- New permission or secret: none; requires existing owner-granted Usage Access and pairing.
