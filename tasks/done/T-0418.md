# T-0418: Notification lifecycle accounting

- Status: done
- Phase: 4.3 / Notification intelligence and dashboard experience
- Depends on: T-0417

## Goal

Repair the notification event model so Roxy can truthfully distinguish a distinct notification object, a later update to that object, and its removal. The model must never label notification events or updates as individual chat messages.

## Read first

- `docs/PRIVACY-SECURITY.md`
- `docs/BATTERY.md`
- Notification listener, metadata entity/DAO, Room migrations, sync contract, hosted event store, and Phase 4 tests.

## In scope

- Metadata-only lifecycle identity and deterministic event semantics.
- Room migration and documented rollback notes.
- Contract/server compatibility and idempotency review.
- Synthetic unit/integration fixtures for one notification, repeated updates, group summaries, removals, and retries.
- Owner-visible wording that says notification activity/updates, never message count.

## Out of scope

- Notification title/body/sender/contact data, notification extras, app-specific message parsing, global tap collection, keystroke capture, Accessibility access, visual dashboard redesign, or new collectors.

## Acceptance checks

- [x] A posted object, its updates, and its removal have explicit deterministic handling without double-counting retries.
- [x] Group summaries remain excluded and no event is presented as a message count.
- [x] Migration, rollback note, contract tests, Android tests, and server checks pass.
- [x] Paired-phone validation records aggregate counts only; no notification content or owner app labels enter logs, fixtures, screenshots, or commits.
- [x] Privacy/battery check: callback-driven only; no polling, foreground service, wake lock, or direct collector network calls.

## Expected resource envelope

- Expected callbacks: unchanged; Android notification callbacks only.
- Expected local rows: at most one lifecycle record per accepted callback, subject to deterministic deduplication.
- Expected uploaded bytes: small metadata envelopes only; no content fields.
- Location / foreground service / wake lock: none.

## Verification record

- Automated: `pnpm check`; Android `testDebugUnitTest` and `assembleDebug`; `git diff --check` all passed.
- Manual paired-phone: rebuilt and installed the debug APK. Aggregate-only synthetic lifecycle validation accepted three callbacks and reported one posted, one updated, and one removed row; the three temporary rows were deleted afterward. The listener remained connected and its queue was empty. No notification content, owner app labels, credentials, payloads, screenshots, or protected data were inspected.
- Battery/privacy: callback-driven listener only; no polling, foreground service, wake lock, direct collector networking, new permissions, or content fields.

## Handoff

- Outcome: lifecycle metadata distinguishes posted, updated, and removed notification activity with local callback deduplication and idempotent upload IDs.
- Files changed: Room schema 8→9, listener/DAO lifecycle handling, contracts/server analytics compatibility, aggregate-safe debug validation, tests, and data-model migration/rollback notes.
- Risks/follow-ups: analytics now exposes `updatedCount`; older server responses remain readable as zero updates during rollout.
