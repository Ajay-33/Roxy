# T-0404: On-device sensitive-field redaction

- Status: done
- Phase: 4 / Notifications
- Estimate: 1–4 hours
- Depends on: T-0403

## Goal

Create a deterministic on-device redaction boundary that removes sensitive notification fields before any future persistence, while preserving the current metadata-only listener behavior.

## In scope

- Implement a pure, allowlisted notification-sanitization model for fields a future opt-in path may submit to it.
- Remove actions, intents, images, remote views, tokens, and likely OTP, account/card, phone, and email strings without logging originals.
- Use synthetic-only fixtures to prove redaction and ensure content cannot reach the listener's metadata table.
- Record redaction occurrence/counts only; do not store removed values.

## Out of scope

- Enabling notification text collection, reading extras in the production listener, selected-app text mode/retention (T-0405), sync/upload, or API changes.
