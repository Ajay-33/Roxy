## Goal

Let the owner understand, grant, and verify Android Usage Access before any app-usage data collection exists.

## In scope

- Declare Android's special Usage Access capability.
- Explain its purpose and limits in the visible app UI.
- Show the current allowed/not-allowed state and open the Android settings destination.
- Refresh state only while the visible app resumes or at owner request.

## Out of scope

- Querying, storing, aggregating, syncing, or displaying usage data.
- Any other Android permission, background collector, service, or polling.

## Privacy note

- Data classes touched: permission state only; it is read transiently and not persisted.
- Redaction/retention impact: none; no usage data is read.
- New permission or secret: `android.permission.PACKAGE_USAGE_STATS`, a user-granted special access; no secret.

## Implementation notes

Usage Access is an owner-visible Android special access. The UI must not imply that it is active before the system reports it as allowed.
