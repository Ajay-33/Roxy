# T-0208: Simplify diagnostic and pairing UI

- Status: done
- Phase: 2 / App usage
- Depends on: T-0207

## Goal

Make the owner-visible Roxy diagnostic screen minimal, clean, and self-explanatory before the three-day physical-phone validation.

## Scope

- Group the flow into clear collection, aggregate export, queue/sync, and connection sections.
- Keep the hosted endpoint and credential entry explicit, with concise guidance and visible paired/queue/sync states.
- Keep detailed counts available only as diagnostics; do not show raw UsageEvents, app labels, or credentials.
- Preserve existing owner-triggered collection and WorkManager behavior. Do not add background polling, services, or permissions.

## Acceptance checks

- [x] The first-use path is understandable without technical labels such as “development endpoint”.
- [x] Pairing, queue, sync, and failure states are visible and concise.
- [x] Existing Android unit tests and debug assembly pass.
- [x] Manual phone check confirms collection, queueing, and sync controls remain reachable.
- [x] Privacy and battery behavior are unchanged.

## Verification record

- Phone check on 2026-08-20: the simplified build installed over the existing debug app; all four sections and the lower connection controls were reachable by scrolling.
- Follow-up on 2026-08-20: **Sync now** was moved from Connection into **3. Send aggregate totals**, so pairing and uploading are not mixed.
- The synthetic developer event control is no longer shown. Existing collection, aggregation, queue, WorkManager sync, encrypted pairing, and privacy behavior are unchanged.

## Battery and privacy

- UI-only change: no new collectors, network calls, wake locks, foreground services, or permissions.
- Credentials remain encrypted locally and are never rendered after entry.
