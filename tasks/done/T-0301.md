# T-0301: Paginated aggregate timeline API

- Status: done
- Phase: 3 / Timeline and exact answers
- Estimate: 1–4 hours
- Depends on: T-0205

## Goal

Provide an authenticated API endpoint that returns a device's uploaded aggregate timeline rows for one explicit local date, with an optional type filter, bounded cursor pagination, deterministic ordering, and an explicit incomplete-data state.

## Read first

- `AGENTS.md`

## In scope

- Add a device-authenticated timeline read endpoint for aggregate event records only.
- Validate date, optional event type, limit, and cursor at the HTTP boundary with Zod.
- Return deterministic newest-first rows and an opaque cursor for the next page.
- Label an empty or partially covered requested local day as incomplete without inferring inactivity or sleep.
- Add focused API/database tests using synthetic, non-personal aggregate fixtures.

## Out of scope

- Android Today/Timeline UI, top-app/total query endpoints, evidence-link endpoints, and timezone regression suite.
- New collectors, permissions, migrations, hosting/deployment changes, or credential changes.
- Raw UsageEvents, app labels, package names, or raw app payloads.

## Acceptance checks

- [x] Automated: valid authenticated requests return aggregate timeline rows only for the requested device/local date, optionally filtered by event type.
- [x] Automated: results are newest-first by occurred UTC instant with event ID as a deterministic tie-breaker; cursor pagination has no gaps or duplicates.
- [x] Automated: invalid/missing date, invalid type, invalid limit, malformed cursor, and unauthenticated requests fail visibly with safe validation/authentication responses.
- [x] Automated: empty or partial requested dates return an explicit incomplete-data state; the endpoint never calls inactivity confirmed sleep.
- [x] Documentation: endpoint contract and incomplete-data semantics are recorded in this task packet and API documentation.
- [x] Manual: HTTP behavior is inspectable through the automated request tests; no physical-phone check is required because Android collection is unchanged.

## Battery note

- Expected rows and upload bytes per day: no additional uploads; response size is bounded by a validated page limit.
- Location/foreground service/wake lock impact: none.
- Required physical-phone measurement: none.

## Privacy note

- Data classes touched: existing uploaded aggregate usage buckets only.
- Redaction/retention impact: none; responses must exclude raw UsageEvents, package names, app labels, and payload contents.
- New permission or secret: none.

## Implementation notes

The endpoint must query authenticated-device rows only. A requested local date is interpreted using each aggregate row's stored observed IANA timezone. Completeness is a conservative coverage label based solely on stored aggregate buckets; it is not a claim about user activity, device use, or sleep.
