- Status: done

## Goal

Provide a polished, local-first browser review shell that communicates Today, Timeline, data completeness, provenance, and privacy without embedding credentials or personal data.

- `AGENTS.md`
- `docs/DESIGN.md`

## In scope

- A responsive dashboard shell with Today and Timeline review states using clearly synthetic, non-personal placeholder data.
- Clear data-completeness, evidence, and unavailable-data presentation.
- A documented authenticated-data integration boundary that keeps device credentials out of browser source and persisted browser storage.
- Build/lint/typecheck/test commands appropriate to the dashboard foundation.

## Out of scope

- Browser access to pairing credentials, hosted deployment, new server/auth service, collection changes, raw event display, or AI.

## Acceptance checks

- [x] Today and Timeline layouts are responsive, accessible, and follow the calm factual design direction.
- [x] Incomplete/empty data and evidence states are explicit; it makes no sleep or inactivity claims.
- [x] The dashboard uses no personal data, package names, credentials, or live device requests.
- [x] Automated dashboard checks pass and the local browser view is manually verified.
- [x] Privacy/battery integration boundary is documented.

## Battery note

- Expected rows and upload bytes per day: none.

## Privacy note

- Data classes touched: none; placeholders are synthetic UI-only values.
- Redaction/retention impact: none.
- New permission or secret: none. Browser integration must not put a pairing credential in source or persistent browser storage.

## Implementation notes

The existing API is authenticated with the paired device credential. A real browser data connection needs a separately designed owner-auth flow; this task deliberately builds the safe presentation foundation first.
